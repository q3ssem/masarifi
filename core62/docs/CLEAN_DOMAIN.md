# 62.6.2 Alpha 1 — clean domain commands

Behavioral reimplementation, not copied legacy business code. New modules use integer halalah, explicit typed commands, immutable transitions, strict field contracts, unique operation IDs, revision guards and before/after audit. Unified obligations support debt, installments, associations, fixed costs and BNPL with explicit amounts and due dates, partial settlement and reversals. Receivables supported. Internal transfers conserve total account cash and are excluded from income/expense ledger. Account archival preserves history. No destructive delete; void is an auditable tombstone. Dates before account opening rejected. Negative account balance permitted to represent reality; no credit decision. No automatic recurrence, installment schedule expansion, split bills, multi-currency or legacy migration in this slice. The audit includes command payload and must be treated as private.

Domain is in-memory and not production storage. Revisions prevent stale writes only within the state passed to execute; actual cross-tab atomic persistence is not integrated. Commands validate full state and clone per operation; 500-command stress is a prototype throughput check, not a production performance claim. UI and legacy bridge unchanged. Production main unchanged. Legacy application is retained only as operational reference pending complete parity; no legacy implementation imported into domain.mjs. No real user data used.

Executed 32/32 source-level JS assertions; 500 sequential commands 892 ms. Reproduce node core62/tests/domain.test.mjs. Next: isolated command UI, recurrence schedules, migration adapters and durable transaction integration, actual browser/real-device test. Release HOLD.
