# 62.6.5 alpha.1 — journal, reports, import and durable encrypted storage

New core journal replays all successful workspace commands into a new session, rejects invalid replay, preserves generated ID counter, caps at 2,000 commands and 8 MiB text. It is a transitional correctness-first design, not scalable production storage. Monthly report separates confirmed/assumed/planned and excludes transfers; CSV quotes fields and guards spreadsheet formulas. CSV import supports only explicit confirmed income/expense rows using the exported schema, not bank/SMS/XLSX formats. Import is atomic into empty session. Native journal restore is complete for current clean workspace data. Legacy v2 preview inspects actual backup schema; only simple records with no meaningful unmapped metadata can pass. Standard real backups with preferences/accounts/debts/schedules etc will be blocked and require specialized mapping. Original source file never modified. No claim of final migration. Legacy encrypted backups not supported. No legacy implementation copied.

Separate IndexedDB journal database stores AES-GCM ciphertext from existing secure-backup module, with generation CAS and previous encrypted revision; encryption before transaction, no plaintext persistence. Explicit password required. Browser storage, cross-tab, crash/quota, encryption integration and runtime UI tests not executed in this call. Source-level 21/21 tests (pure journal, reports, import, CAS). Main untouched, release HOLD.
