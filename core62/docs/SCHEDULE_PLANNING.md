# 62.6.3 Alpha 1 — clean recurring schedules and planning

New schedule engine is independent of old code. Monthly anchor clamping, intervals 1–12 months, finite counts or open-ended rules, explicit dates, stable occurrence IDs, bounded expansion, no automatic payment or income confirmation. An occurrence may be materialized as a unified obligation; repeated materialization is idempotent and mismatched amounts block. Partial payments reduce the remaining planned amount; full payment removes it; void restores it. Recurring income maps to an incoming receivable in the current domain, subscriptions to fixed obligations. This mapping is transitional; no legacy auto-payment assumptions or historical estimates migrated. The caller must supply a complete range including outstanding older obligations, and must avoid representing one real transaction both as an independent record and a settlement. Non-scheduled obligations are not automatically included by scheduledLedger. 

Budget overview wraps existing envelope engine and reports unbudgeted confirmed spending. Goal progress is a separate analysis, not a wallet balance or automatic cash movement; monthly target uses month difference (not exact days). Goals/contributions not persisted in domain. No UI binding, no storage, no cloud, no real device test. All new code is clean reimplementation. No legacy data touched. 30/30 source-level assertions; 12000 synthetic schedule occurrences in 28 ms. Reproduce node core62/tests/schedule-planning.test.mjs. Main unchanged, release HOLD.
